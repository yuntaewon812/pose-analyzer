# 🐬 수중 돌핀킥 동작 분석

정답 영상과 내 영상의 **수중 돌핀킥**을 관절 각도로 비교해, 어느 관절을 어떻게
고쳐야 하는지 알려주는 프로젝트.

수영 영상은 대개 영법이 섞여 있어서(다이빙 → 돌핀킥 → 자유형 → 턴 → 돌핀킥 → …),
**영상에서 돌핀킥 구간을 자동으로 찾아내는 것**부터 시작한다.

## 결과물

- **관절별 집중 비교 영상** — 차이가 큰 관절마다 영상 1개. 내 동작 쪽 그 관절
  하나에만 노란 동그라미를 표시해서, 한 번에 한 곳만 보면 되게 했다.
- **정면/측면 비교 영상** — 정답과 내 동작을 나란히, 같은 진행률에서 재생
- **영상별 피드백** — "왼쪽 무릎을 더 펴세요 (덜 접고 차보세요)" 같은 행동 지시문

## 빠른 시작 (앱)

```powershell
python -m venv venv                      # 처음 한 번만
.\venv\Scripts\python.exe -m pip install -r requirements.txt
.\venv\Scripts\streamlit.exe run src\app.py
```

의존성은 `venv` 안에만 설치되므로, 스크립트를 직접 돌릴 때도
`.\venv\Scripts\python.exe src\...` 형태로 가상환경 파이썬을 지정한다.

앱에서 정답 영상과 내 영상을 올리고 **분석 실행**을 누르면, 돌핀킥 구간 검출부터
비교 영상 생성까지 자동으로 진행된다. 영상 길이에 따라 몇 분 걸린다(관절 추출이 대부분).


## 피드백 문장을 AI로 (선택)

기본은 규칙 기반입니다 — 미리 적어둔 표에서 문장을 꺼내므로 항상 같은 답이 나오고
검증하기 쉽지만, 관절마다 표현이 반복됩니다. Claude API 키가 있으면 같은 숫자를
바탕으로 관절마다 코치가 말하듯 문장을 만들 수 있습니다.

**1. 키 발급** — [console.anthropic.com](https://console.anthropic.com) → API Keys →
Create Key. `sk-ant-`로 시작하는 문자열을 복사합니다 (한 번만 보여주므로 바로 저장).

**2. 환경변수로 설정** — 키는 코드에 적지 마세요. 실수로 깃에 올라가면 폐기해야 합니다.

```powershell
$env:ANTHROPIC_API_KEY = "sk-ant-..."     # PowerShell (창을 닫으면 사라짐)
```
```bash
export ANTHROPIC_API_KEY="sk-ant-..."      # Git Bash
```

창을 닫아도 유지하려면 PowerShell에서 한 번만:
```powershell
[Environment]::SetEnvironmentVariable("ANTHROPIC_API_KEY", "sk-ant-...", "User")
```
(설정 후 터미널을 새로 열어야 적용됩니다.)

**3. 실행** — 앱을 켜기 전에 한 번 돌리면 됩니다.

```powershell
.\venv\Scripts\python.exe src\generate_feedback_llm.py
```

가상환경의 파이썬을 직접 지정하는 방식입니다. 그냥 `python`으로 실행하면 시스템
파이썬이 잡혀서 `ModuleNotFoundError: No module named 'anthropic'`이 납니다
(의존성은 `venv` 안에만 설치돼 있습니다).

`output/comparison/feedback_llm.json`이 만들어지고, 앱이 이 파일을 발견하면 관절별
영상 아래 문장을 LLM 문장으로 바꿔서 보여줍니다. **키가 없어도 앱은 정상 동작합니다** —
파일이 없으면 규칙 기반 문장을 그대로 씁니다.

비용은 관절 8개 분량 한 번 호출이라 얼마 되지 않지만, 실행할 때마다 과금됩니다
(분석을 다시 돌렸을 때만 재실행하면 됩니다).

## 돌핀킥을 어떻게 찾아내나

측면 촬영에서는 두 발목이 화면에서 거의 겹쳐(몸통의 0.07~0.14배) **좌우 다리 구분이
불가능**하다. 그래서 "돌핀은 두 다리가 함께, 플러터는 번갈아"라는 구분은 쓸 수 없고,
대신 겹침에 영향받지 않는 네 가지를 본다:

| 특징 | 돌핀킥 | 자유형 | 글라이드 |
|---|---|---|---|
| 팔 움직임 (손목 변동) | 0.05 | **0.31** | 0.02 |
| 좌우 어깨 비대칭 | 5° | **81°** | 5° |
| 팔 뻗음 (양쪽 어깨 각도) | 165° | 144° | 168° |
| 발끝 진폭 | 2.04 | 1.19 | **0.86** |

팔 움직임·어깨 비대칭이 자유형의 "팔 젓는 순간"을 걸러내고, 발 진폭·주기성이
글라이드를 걸러낸다. (무릎 검출률은 여기에 넣지 않는다 — 아래 "돌핀킥인가와
분석할 수 있는가는 다른 질문이다" 참고.)

**하지만 위 네 가지로는 부족했다.** 자유형 영상 2개로 검증했더니 7곳이 돌핀킥으로
잘못 잡혔다. 자유형에도 팔을 뻗고 미끄러지는 **글라이드 순간**이 있는데, 그 1초 동안은
팔 움직임(0.006~0.126)도 어깨 비대칭(0°)도 돌핀킥과 구분되지 않고, 플러터킥의 발
진폭(1.04~1.67)마저 진짜 돌핀킥(1.72)과 겹쳤다. 그래서 두 가지를 더 본다:

| 추가 기준 | 근거 |
|---|---|
| 엉덩이 상하 진폭 ≥ 0.30 | 돌핀킥은 몸 전체가 물결쳐 엉덩이가 오르내리지만, 플러터킥은 엉덩이를 고정한 채 다리만 젓는다 |
| 구간 길이 ≥ 2.0초 | 진짜 돌핀킥은 연속으로 여러 번 차지만, 자유형 글라이드는 1~1.75초로 짧게 끊긴다 |

## 분석 대상 범위

이 프로젝트가 보는 것은 **수중 스트림라인 돌핀킥** — 다이빙이나 턴 직후 물속에서
양팔을 앞으로 모아 뻗고 몸을 물결치며 나아가는 국면이다. **수면에서 하는 접영은
대상이 아니다.** 접영도 다리 동작 자체는 돌핀킥이지만, 팔이 스트로크를 하고 있어
자세가 완전히 다르고 비교 기준이 되지 못한다.

접영 영상에서도 스타트·턴 직후의 수중 구간은 대상에 포함되며, 실제로 검출된다
(아래 test4 참고).

## "돌핀킥인가"와 "분석할 수 있는가"는 다른 질문이다

검출기는 두 가지를 **따로** 판정한다.

- **동작 판정** — 팔 자세·발 진폭·엉덩이 물결·구간 길이로 "이게 돌핀킥인가"를 본다.
- **품질 판정** — 무릎이 충분히 검출됐는지로 "이 구간을 분석할 수 있는가"를 본다.
  이후 단계가 무릎 각도를 기준 신호로 쓰기 때문이다.

둘을 한데 묶으면 **"무릎이 안 보임"이 "돌핀킥 없음"으로 보고**돼서, 새 영상에서
무엇이 문제인지 알 수 없다. 실제로 접영 영상에서 그런 일이 있었다 — 스타트 직후
돌핀킥을 제대로 찾아놓고도 "0개"로 보고했다. 지금은 이렇게 나온다:

```
돌핀킥 동작 구간: 1개  (그중 분석 가능: 0개)
  #0    4.25 ~   8.75초  (4.50초)  발끝진폭 1.63  [분석 불가 - 무릎 검출 18%]
  → 돌핀킥은 찾았지만 무릎이 충분히 검출되지 않아 비교 분석을 할 수 없습니다.
```

## 검증 결과 (영상 6개)

| 영상 | 실제 | 동작 검출 | 분석 가능 |
|---|---|---|---|
| reference | 다이빙 직후 + 턴 직후 돌핀킥 | 2개 ✅ | 1개 (다이빙 직후는 무릎 24%) |
| mine | 다이빙 직후 + 턴 직후 돌핀킥 | 2개 ✅ | 1개 (다이빙 직후는 무릎 0%) |
| test1 (자유형) | 없음 | 0개 ✅ | — |
| test2 (자유형) | 없음 | 0개 ✅ | — |
| test3 (개인혼영) | 스타트·턴 직후 | 3개 ✅ | 1개 |
| test4 (접영) | 스타트 직후 | 1개 ✅ | 0개 (무릎 18%) |

자유형 2개에서 **오검출 0건**, 돌핀킥이 있는 4개에서 **모두 검출**했다.

⚠️ 기준값은 이 6개 영상으로 정한 것이라 표본이 적다. 새 영상에서 틀리면
`detect_dolphin_kick.py` 상단 상수를 조정하되, **반드시 기존 6개로 다시 확인**해야
한다 — 하나를 맞추려다 다른 것이 깨지기 쉽다.

## 접영 킥과 수중 돌핀킥은 아직 동작만으로는 못 가른다

접영은 입수킥·출수킥 두 번이 번갈아 나오고 수중 돌핀킥은 균일하게 이어지므로,
발차기 리듬으로 구분할 수 있으리라 보고 시도했다. 결과는 실패였다 — 킥 크기가
번갈아 달라지는 정도(교대지수)가 접영 0.27~1.78, 수중 돌핀킥 0.38~0.89로 완전히
겹쳤다. 팔 움직임으로 가르는 방법도 마찬가지였다(자유형에는 통하지만 접영은
양팔이 대칭이라 통하지 않는다).

현재는 **팔이 앞으로 모여 뻗은 스트림라인 자세**를 요구하는 것으로 접영의 스트로크
구간을 배제하고 있다. 리듬 기반 구분을 제대로 하려면 무릎·발끝 검출 품질을 먼저
끌어올려야 한다(현재 접영 영상 무릎 검출 30%).

구간을 못 찾으면 **탈락 사유를 함께 출력**한다 — 기준을 조정해서 될 일인지, 아니면
데이터가 아예 없는지 구분할 수 있어야 하기 때문이다.

## 알려진 한계

- **다이빙 직후 돌핀킥은 분석하기 어렵다.** 물거품 때문에 무릎 검출률이 0~53%까지
  떨어진다. 기준을 낮춰서 될 일이 아니라 데이터가 없는 경우다. 턴 직후 구간이
  비교적 잘 잡힌다.
- **몸이 옆으로 누운 구간은 측정이 안 된다.** 롤이 크면 킥의 약 49%가 카메라 깊이
  방향으로 일어나는데, 카메라 한 대로는 그 성분을 원리적으로 잘 볼 수 없다.
  `segment_reps.py --max-roll`로 그런 구간을 제외한다. 제대로 풀려면 카메라 2대가
  필요하다.
- **포즈 추정 도구는 MediaPipe가 가장 나았다.** RTMPose·YOLO11(n/x)과 같은 클립에서
  비교한 결과, 검출률은 RTMPose가 높았지만 뼈 길이 일관성(관절 위치 정확도의 지표)이
  MediaPipe 9~18% vs 32~218%로 크게 뒤졌다. 재현: `python src/benchmark_pose_tools.py`

## 다른 동작에 쓰려면

지금은 돌핀킥 전용이다. 바꿔야 할 값은 대부분 상수로 모여 있다:

- `generate_feedback.py` — `PHASE_TITLE`, `CYCLE_LABEL`, `JOINT_HINTS`, `ACTION_VERBS`
- `run_pipeline.py` — `DOLPHIN_KICK_ARGS` (기준 관절, 스트림라인/롤 필터)
- `detect_dolphin_kick.py` — 판정 기준값 (파일 상단)

단, 측면 뷰(`pose_projection.py`)는 **몸이 수평으로 누운 상태**를 전제하므로,
서 있는 동작(스쿼트 등)에는 3D 기반 투영으로 되돌려야 한다.
